# Fail closed before any clinical card

MedSwin should reinforce the control plane it already runs: a Python evidence gate that is the only authority for accept, with synthesis and a CDS Hooks card allowed only after that gate passes, and with the inclusion bar left at **0.55**. The defects that change a clinical decision are not a missing agent framework. A missing calibrated score can still clear inclusion through a fusion fallback. A same-drug warning on another facet never becomes a conflict, while a negated caution becomes a high conflict the critic cannot clear. A duplicate retrieve page jumps the loop to the last iteration and abstains. Retrieval can score the wrong patient, the wrong dense scale, or a short weak passage that fails the all-passage vote. A valid `patient-view` with no question returns **HTTP 200 and no cards**. Sessions bind to the organisation and not the user. The live verifier can record **PASSED** while both pipelines abstain. The repair is fail-closed at each of those points, the shipped same-drug rule applied to the full passage, a card and a trace that name the decision that ran, and a small deterministic test of that trace. A local 7B model at a 2048-token window can run that fixed graph. It cannot run a lead model that spawns specialists or a progress ledger over the full transcript. This pass states no MedSwin clinical score. The audits did not read `.env`, and they did not execute the test suite.

## A missing calibrated score must not clear 0.55

The live decision is `EvidenceGate.decide`. The orchestrator builds a ledger, ranks, packs, and then asks the gate about the packed bundle. Inclusion is a real vote. Every selected passage must clear **`SUFF_T_INCLUSION` 0.55**, and the mean must clear **`SUFF_T_MEAN_CONF` 0.60**. Those defaults live in `app/core/config.py`. The orchestrator-gate ledger and the retrieval ledger both read them, and both refuse any repair that lowers 0.55. An earlier reading that those two settings were only startup range checks is superseded by that code path. What the vote actually compares is the first present value among calibrated, rerank, fusion, and dense. An explicit **0.0** stays 0. A missing calibrated score does not. After a rerank exception, `rank` still writes `fusion_score`. Fusion uses a default relevance of **0.50** when calibrated and rerank are both missing, and a strong CPG hit can still clear 0.55 with no calibrated score. The mean-confidence vote uses the same fallback ([orchestrator and gate ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/orchestrator_gate_gaps.md), [retrieval and scoring ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/retrieval_scoring_gaps.md)).

The accept rule that matches those ledgers is narrow. Compare a present calibrated score with the current 0.55 and 0.60. Fail inclusion and mean confidence when `calibrated_score` is missing. Do not substitute fusion, and do not add an eval-only override that accepts the uncalibrated order. A rerank failure has a second, opposite bug. The ledger is built before `rank()`, so relevance is stored as **0.0**, every facet contribution is 0, and the gate retrieves and then abstains even when dense hits are good. `enable_reranker` is never read. Both pipelines set it true, so the live bypass is the exception path. On that path, mark the trace degraded, build facet coverage after fusion, and use the dense cosine as relevance so a good neighbour is not scored as zero. Keep the abstain when the dense evidence is actually weak. The inclusion vote still requires the calibrated score. A dense cosine fills the facet trace for the next retrieve. It does not mint an accept. ([retrieval and scoring ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/retrieval_scoring_gaps.md)).

Packing fights that vote before the gate sees it. Selection ranks by utility per token and stops only at **`SUFF_MIN_MARGINAL_UTILITY` 0.0002**. The gate then demands that every packed passage clear 0.55. The retrieval ledger works an example from the defaults. A short literature background passage with rerank probability 0.30 fuses to **0.446**. At 3 tokens its utility is about **0.196 per token**. A strong CPG passage at rerank 0.93 fuses to **0.844**. At the configured 400-token chunk that is about **0.0027 per token**. The weak passage wins the greedy step. A 400-token weak passage is still about **0.00147 per token**, above the stop line, so the stop does not drop it. One score under 0.55 turns accept into retrieve-more, then abstain on the last loop. The policy tests set scores to 0.92 and never run this packer. Drop passages whose fusion score is below 0.55 before the inclusion vote. Keep a short passage only when that score clears 0.55. Leave the threshold where it is ([retrieval and scoring ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/retrieval_scoring_gaps.md)).

The retrieve loop then spends that failure badly. On loop 1 or later, a retrieve that adds no new chunk id rewrites the gate iteration to **`MAX_RETRIEVE_LOOPS - 1`** (default 2) and breaks. `can_retrieve_more` becomes false, so a still-missing facet or an open conflict becomes `INSUFFICIENT_EVIDENCE` at once. Hints from that check are never retrieved. One duplicate page skips a remaining loop, and the audit row records the last iteration, not the iteration that ran. The end-to-end test covers a two-call retrieve that does add a new safety chunk. It does not return the same chunk ids before the last loop. Pass the real iteration into the gate. Continue while the action is retrieve-more and the cap allows it. Stop when the hint set is unchanged, so a duplicate page cannot spin. A `guideline_only` pin makes this worse: it forces CPG for every loop, the safety hint never wins, and the duplicate-page jump abstains with the safety facet still missing. Let a safety or chart hint override that pin for one loop, or abstain at once when the constraint forbids the source the gate needs ([orchestrator and gate ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/orchestrator_gate_gaps.md)).

That stop is the clinical one the production SDKs do not ship. LangGraph’s recursion limit, from version 1.1.4, defaults to **10,007** super-steps and raises `GraphRecursionError` when exceeded. It does not define an evidence-diff stop ([LangGraph Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)). The OpenAI Agents SDK raises `MaxTurnsExceeded` past `max_turns`, and `max_turns=None` disables the cap. The fetched running-agents page does not state a numeric default ([OpenAI Agents SDK](https://openai.github.io/openai-agents-python/running_agents/)). Magentic’s progress ledger asks a model whether progress is being made. AutoGen increments a stall counter and replans at `max_stalls`. Semantic Kernel’s default stall count is 3, and its comparison is `>` where AutoGen uses `>=`, so the same configured 3 does not fire on the same round ([AutoGen MagenticOne](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_magentic_one/_magentic_one_orchestrator.py), [Semantic Kernel Magentic](https://github.com/microsoft/semantic-kernel/blob/c781da13/python/semantic_kernel/agents/orchestration/magentic.py)). Anthropic’s June 2025 research system left the loop when the lead judged the information sufficient. Effort bands were prompts. Early runs spawned **50** subagents for sources that did not exist ([Anthropic multi-agent research system](https://www.anthropic.com/research/multi-agent-research-system)). KnowGuard stops on whether a bounded pool of knowledge-graph triplets is sufficient, and it keeps the top K across rounds rather than restarting. Those accuracy and turn-count figures are the authors’ own ([KnowGuard](https://arxiv.org/abs/2509.24816)). MedSwin already has the right shape of cap, **`MAX_RETRIEVE_LOOPS` 3**, and the right comparison, the set of chunk ids. The reinforcement is to honour the real iteration and to treat “no new evidence” as a successful abstain, not as a rewritten counter and not as an exception the HTTP layer turns into a generic error.

Two neighbouring false abstains belong in the same lock, and neither is a reason to move 0.55. For one document the facet lower bound subtracts a flat **`SUFF_LCB_MARGIN` 0.08**. A single excellent guideline, alignment saturated, rerank 0.90, grade 0.95, contributes **0.855**. The bound is **0.775**, under the critical facet bar of **0.78**. At rerank 0.91 the bound is **0.785** and the facet passes. For one deterministic contribution, compare 0.78 with the contribution itself. Keep the bootstrap bound when two or more documents support the facet. Separately, a dense or lexical exception returns an empty list, the loop repeats the same filters, and the clinician sees abstain rather than “retrieval failed”. Stop on that error. Naive RAG already names an empty corpus. The gated agent should name a failed retrieve ([retrieval and scoring ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/retrieval_scoring_gaps.md)). `SUFF_T_CPG` and `SUFF_T_EMR` remain **2** and still only scale reported kappa. They do not accept or reject. If the product means them as sufficiency counts, put them in the bundle predicate when those facets are required. If they are audit-only, stop treating the names as thresholds. The scoped tests monkeypatch inclusion to 0.99 and do not lock the live defaults, so a silent edit of 0.55 still passes the suite ([orchestrator and gate ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/orchestrator_gate_gaps.md)).

## Same-drug conflicts stay paired, and false conflicts stay unresolved

The shipped `same_intervention` rule stays closed. A caution pairs only when both texts name the same drug, or when neither text names a drug. The holes are places where that rule never sees the pair, or where it sees a pair that the words do not support. FDA’s non-device CDS examples tie drug-interaction and contraindication notices to patient-specific information and a known source, including a drug-disease case such as asthma and a non-selective beta-blocker ([FDA CDS guidance](https://www.fda.gov/media/109618/download)). A concise CPOE pattern binds a contraindication to a specific prescribed drug ([PMC5133218](https://pmc.ncbi.nlm.nih.gov/articles/PMC5133218/)). Across three references, **17 of 30** drug value sets had nonsignificant agreement, and **33** risk-modifying factors could change the real risk in **14 of 15** interactions ([PMC9218784](https://pmc.ncbi.nlm.nih.gov/articles/PMC9218784/)). Textual contradiction is a different test. Moving from most-similar to most-contradictory retrieval dropped average R1 by **18.2%** in one healthcare RAG study ([When Evidence Contradicts](https://arxiv.org/html/2511.06668v1)). Reversing document order changed **11.4% to 25.2%** of predictions when a correct and a contradictory document were mixed ([HealthContradict](https://aclanthology.org/2026.bionlp-1.50/)). The operational reading is entity match first, then a conflict on that span. MedSwin’s shipped rule is already that match. The ledger does not reopen the neither-names-a-drug branch.

The miss that hides a real contraindication is cross-facet. `detect_contradictions` pairs only inside one facet. On `safety_contraindications`, polarity `SAFETY` is support, not a contradict. A safety monograph that lacks guideline keywords scores 0 on `guideline_concordance` because a source bonus of 0.15 sits under 0.45, so the facet is dropped and no claim is built. The guideline passage can satisfy guideline coverage. The warning can satisfy safety coverage. The gate can accept. No scoped test puts the same drug on a guideline support claim and a safety warning that lacks guideline keywords. The repair is to pair a `SAFETY` or `CONTRADICTS` claim on the safety facet with a `SUPPORTS` claim on each other facet when `same_intervention` is true for those two strings ([orchestrator and gate ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/orchestrator_gate_gaps.md)).

Three further misses drop that pair before the gate. Retrieval claims store the first **280** characters. A drug named after the cut looks unnamed, and the one-sided branch skips the pair. `detect_contradictions` also joins every claim on the ledger entry, not the claims for the facet in the pair, so an off-facet warfarin claim makes the support side “named” and an unnamed caution on the facet under test is dropped. Run the rule on the two claims for that facet, and keep a drug alias from the full passage. Contradiction detection also runs on the packed bundle. A caution is protected only when its safety or contradiction score is at least **0.48**, and each hit adds **0.16**. The text “Avoid apixaban. Apixaban is contraindicated.” scores **0.32** and can be dropped when the bundle is over the token budget. The gate then never sees the conflict. Run detection on the pre-pack pool, or pin same-intervention caution chunks before the utility drop ([orchestrator and gate ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/orchestrator_gate_gaps.md)).

The false critical conflict is the mirror image, and it is the one clinicians act on. Caution language is a substring. `contraindicat` matches “no contraindications”. `do not` matches “do not delay”. On a non-safety facet that polarity is `CONTRADICTS`. With a CPG grade of **0.95** the pair is severity **high**. High pairs are not adjudicated. The gate retrieves more, then abstains. A negated contraindication becomes a conflict that cannot clear. Treat a caution span as a conflict only when a local negation does not govern it. Keep the unnegated “avoid” and “contraindicated” path. The drug lexer mis-labels the same intervention on top of that. `nsaid` and `nsaids` do not intersect. A hyphenated token does not intersect its stem. `endswith("pril")` marks `april` as a drug, so “Recommend lisinopril in April” pairs with “Avoid therapy in April” on the false token. Compare stems, fold a simple plural onto the listed form, split hyphenated tokens before the suffix test, and drop a suffix hit that is not a drug. The different-drug test already locks apixaban against dabigatran. It does not lock plurals, hyphens, or April ([orchestrator and gate ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/orchestrator_gate_gaps.md)).

`unless`, `except`, `caution`, and `monitor` become `QUALIFIES`, and `QUALIFIES` is support. “Use apixaban with caution in CKD” does not conflict with “Apixaban is recommended”, and the warning counts as coverage. Treat same-intervention `QUALIFIES` as a conflict against an unqualified recommendation, at a weaker severity than avoid or contraindicated. That split matches the display rule in the literature. Interruptive alerts are for the most serious interactions. Indiscriminate interruptive alerts add noise ([PMC11737836](https://pmc.ncbi.nlm.nih.gov/articles/PMC11737836/)). **17%** of time-dependent interaction alerts in one CPOE study were false positives because the separation interval was already prescribed ([PMC3002121](https://pmc.ncbi.nlm.nih.gov/articles/PMC3002121/)). False-positive CDS alerts increased commission errors by **65.8%** in the low-complexity arm of an e-prescribing study, and incorrect CDS increased omission errors as well ([PMC5356416](https://pmc.ncbi.nlm.nih.gov/articles/PMC5356416/)). A weaker same-drug caution should surface. It should not take the unblockable high-severity path.

The critic must not paper over either error. Medium and low conflicts are marked resolved for the whole bundle. Any critic note containing “outdated”, “obsolete”, “superseded”, or “population mismatch” sets one global stale flag and clears every unresolved medium pair, including a pair the critic did not name. Separately, a grade gap of **0.25** resolves a medium pair when the critic said nothing. Default chart grade **0.70** versus a case-report grade **0.38** is a gap of **0.32**, both under 0.80, so the pair is medium and is cleared. `SUFF_MAX_CONTRADICTIONS` is **0**, so a resolved pair no longer blocks accept. Two-stage never calls adjudication. Full mode can accept a conflict that two-stage still blocks. No test calls `adjudicate_contradictions`. Resolve one pair only when the critic cites that pair’s chunk ids and states a stale or mismatch reason. Remove the grade-gap branch, or require the higher grade to be the support side and a pair-specific citation. High-severity pairs stay unresolved. The critic has no structured resolved flag, and the gate blocks accept on any unresolved high pair. Do not add a keyword path that clears high severity. Do not raise `SUFF_MAX_CONTRADICTIONS` to make abstention rarer ([orchestrator and gate ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/orchestrator_gate_gaps.md), [specialist agent ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/specialist_agent_gaps.md)).

Coverage can also accept a bundle that only says not to use the therapy. A `CONTRADICTS` claim still adds coverage, at **0.35** of confidence times relevance times grade. Several contradict-only documents can clear a facet. If the support bucket is empty, detection emits no pair, the facet is not missing, and the gate can accept. Give `CONTRADICTS` a coverage contribution of 0, and do not mark a facet satisfied when it has no supporting chunk. A numeric LLM facet threshold above 1 is kept, lower bounds clamp to 1, and that required facet can never pass, so the gate retrieves and then abstains. An extra LLM facet defaults to required. Clamp thresholds to the configured ceiling and to 1, and keep LLM-only facets optional unless the caller listed them. `patient` and `elderly` are substrings, so “outpatient” and “nonelderly” force a required chart facet and an exclusive chart retrieve that finds nothing. Match whole words. Require the chart facet when a patient id is present or the caller lists the facet ([orchestrator and gate ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/orchestrator_gate_gaps.md)).

## The gate only sees the evidence retrieval actually kept

Several high-severity retrieval bugs change the candidate set before any of the pairing rules run. Dense scores are not on one similarity scale. HNSW cosine distance converts with `1 - distance`. FAISS IVF stores squared L2 after normalisation, so the same line stores `2 * cosine - 1`. The hybrid list then min-maxes dense scores. The best neighbour becomes 1 and the worst becomes 0, even when both cosines are high. Fusion treats those values as probabilities at weight **0.25**. The retrieval ledger’s arithmetic on the defaults: true cosine 0.80 is an HNSW score of 0.80 and a FAISS score of **0.60**. With no rerank score, fusion is **0.610** on HNSW, which passes the 0.60 mean gate, and **0.598** on FAISS, which fails it. Two neighbours at cosine 0.91 and 0.90 become dense 1.0 and 0.0, and their no-rerank mean is **0.592**, so the mean gate fails. Left as raw cosines, the same pair passes. A FAISS neighbour at true cosine 0.70 can lose to an HNSW neighbour at true cosine 0.50, so the better chunk misses the rerank pool. Convert FAISS squared L2 to cosine with `1 - distance / 2` before the merge. Stop min-maxing scores that are already cosine similarities. Keep the raw cosine for the gate. The audit did not open a live index file. A missing FAISS index is skipped. An HNSW-only deployment still has the min-max defect ([retrieval and scoring ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/retrieval_scoring_gaps.md)).

Facet coverage then credits the wrong text. The comment says source affinity alone must not mark a facet covered. The code zeros the facet only when `source_bonus` is under **0.45**. An exact source match returns 0.45, so the guard does not run. Any CPG chunk covers guideline concordance with no keyword hit. Any chart chunk covers patient applicability with no chart language. With the ledger’s worked example, two CPG documents at rerank 0.90 and grade 0.95 contribute enough for a noisy-OR of **0.856**, above the critical bar **0.78**. Two chart documents at rerank 0.90 and grade 0.70 reach **0.705**, above the patient bar **0.70**. If no keyword matched and the safety bonus is 0, set the facet score to 0, including on an exact source match. Keywords themselves are substrings. “age” hits inside “management”. “lab” hits inside “available”. “recommendation” does not hit “recommended”, and “contraindication” does not hit “contraindicated”, though the safety stem `contraindicat` does. Two CPG passages whose text is “Management recommendation discusses cardiovascular risk.”, at rerank 0.92 and grade 0.95, clear guideline, safety, and evidence on the first loop without stating a contraindication. On the next loop the same “management” substring can clear patient applicability with no chart. Match whole tokens, or a small stem list. Remove bare `age`, `lab`, and `risk`. Add `recommended` and `contraindicated` as explicit terms. Because those false covers mark the guideline facet done, the source probe never fetches CPG. When the source policy is open, the retriever probes literature, chart, and safety. It does not probe guidelines. Add CPG to that probe list with the same half-k budget ([retrieval and scoring ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/retrieval_scoring_gaps.md)).

Patient scope fails in the same layer. The full-text query filters organisation and sometimes source type. The `patient_id` branch is an empty `pass`. Patient filtering happens only after a limit capped at **2000**. Other patients’ notes fill that window, and the target chart never reaches the database. The orchestrator also appends up to **140** words of the chart onto the shared query, so those words match other notes. The Mongo filter, when a patient id is set, keeps every chunk whose source type is not chart, even when that chunk carries a different patient id. A chart stored as literature, safety, or a blank source type therefore matches every patient in the organisation. The chart agent, if its filtered list is empty, falls back to the whole pool. Shared passages still send the full pool to the claim prompt. If a chunk has a patient id, return it only when that id equals the request patient. Put the same predicate in the full-text clause for chart rows. Delete the fallback that widens an empty specialist filter to every candidate. Reject chart ingest when the patient id is empty, because a null id matches neither side of the current filter. The tests cover a named patient and a missing patient. They do not cover a chart row with a null id, and they do not build the full-text `WHERE` clause ([retrieval and scoring ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/retrieval_scoring_gaps.md), [API, CDS, and session ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/api_cds_session_gaps.md)).

The shared ANN can drop the tenant that has the evidence. One HNSW index is built with `org_id=None`. The query embeds against that global index, then Mongo keeps the organisation. Exact recovery runs only when the filtered count is at most **5000**. Above that, the helper returns no exact hits. A larger tenant whose best chunks sit outside the global neighbour cap, at most 500 and 320 when k is 80, gets an empty or partial dense set. The label map stores `chunk_id` only. Uniqueness is organisation plus chunk id, so the same chunk id in another organisation can attach that organisation’s neighbour score to this organisation’s text. Store the organisation with the label, or build one index per organisation. If the filtered count is above 5000, raise the neighbour cap for that organisation. No production sample of colliding chunk ids was checked. The unique index allows the collision ([retrieval and scoring ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/retrieval_scoring_gaps.md)).

Utility ranks the warning above the recommendation and then the warning trips the gate. `CONTRADICTION_PENALTY_WEIGHT` **0.40** is never read. Utility adds `0.12` times the contradiction score. In the ledger’s example a warning outranks a slightly stronger clean passage, **1.117** versus **0.933**, and the packed warning becomes an unresolved high conflict. Subtract the configured penalty inside marginal utility. Keep the safety-preserve rule so the warning stays in the bundle for the gate to see. Provenance failures need the same retrieve-more treatment as a confidence gap. A non-empty bundle that fails only provenance does not retrieve more. When required facets are already covered, marginal utility is 0, which is not above 0.0002, so iteration 0 abstains and a later retrieve cannot replace the weak passage. Empty bundles still loop, because their marginal utility is forced to 1.0. No application writer in the audited files sets `weak_provenance`. The gate branch is real. How often ingest sets it was not measured ([orchestrator and gate ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/orchestrator_gate_gaps.md), [retrieval and scoring ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/retrieval_scoring_gaps.md)).

Vector identity stays a hard boundary beside these scoring fixes. A MedEmbed index at **1024** dimensions and a Bedrock Cohere Embed v4 index at **1536** dimensions are different spaces. The local research cell and the mild cloud path each keep one space per index. The gate does not repair a query that was embedded in the other space. Cloud health already returns **503** when an existing index does not match the active embedder. Eval that forces a cloud embedder and then reads the result as a local retrieve does not exercise this gate ([architecture design note](../research_notes/MedSwin%20agentic%20runtime%20quality/architecture_design.md)).

## The card, the session, and the trace must name one decision

CDS Hooks 2.0.1 requires every card’s `indicator` to be `info`, `warning`, or `critical`, in that order of urgency. The client may use the value for sort order or colour. The card table does not mandate a workflow block. HL7’s current code system, active 27 October 2026, defines critical as high urgency that is immediately addressed. The older FHIR R4 sentence that critical means the workflow should not proceed is absent from the 2.0.1 card table ([CDS Hooks 2.0.1](https://cds-hooks.hl7.org/STU2/), [HL7 cdshooks-indicator](https://terminology.hl7.org/en/CodeSystem-cdshooks-indicator.html)). The service is registered for `patient-view`. That hook requires a user and a patient. It does not define a question. When `context.question` and `context.clinicalQuestion` are blank, the handler returns `{"cards": []}` and does not call the gate. The tests lock that empty result. A conformant call therefore shows the clinician nothing. Treat a missing question as one warning card that names the patient and says the hook did not include a clinical question. Empty cards remain a legal “no guidance” result in the specification. They are the wrong result for a patient-view the product registered and then declined to run ([API, CDS, and session ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/api_cds_session_gaps.md)).

A crashed decision is shown as insufficient evidence, and the card cannot be joined to the trace. `cards_from_chat` always emits one card after the gate runs. The uuid is a new random value and is not stored. The card has no trace id, hook instance, or patient id. `degraded_mode` is ignored. The orchestrator error response has no policy decision, so the card uses indicator warning, the summary “The available evidence is insufficient.”, and the detail “No sufficiency decision was recorded.” The user-facing error sentence is dropped. On an accepted card, the clinical summary removes the leading clinician-boundary sentence, and the tests lock that removal. A client that shows only `summary` does not show the boundary. On a degraded error or a missing policy decision, return one card with indicator **critical** and a system-failure summary. Put the trace id, the hook instance, and the patient id in a card extension, store that same card uuid on the trace, and keep the boundary sentence in the summary. An accepted card still requires a passed decision, action accept, non-empty passages, and no unresolved critical conflict. Do not synthesise on insufficient evidence in order to fill a helpful card. FDA criterion 4 and the TGA exemption both turn on a professional who can review the basis and is not asked to rely on the software as the decision. The TGA exemption amendments effective **1 November 2026** are described as clarity changes, with the exemption scope left as it was ([API, CDS, and session ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/api_cds_session_gaps.md), [FDA CDS guidance](https://www.fda.gov/media/109618/download), [TGA CDSS guidance](https://www.tga.gov.au/resources/guidance/understanding-clinical-decision-support-system-software-regulation), [TGA exemption amendments](https://www.tga.gov.au/news/news-articles/clinical-decision-support-system-exemption-amendments)).

The stored trace can disagree with that card. The loop appends the gate decision, and a later replacement can write `INSUFFICIENT_EVIDENCE` into the final fields without appending it to `policy_decisions`. The last entry can still say the gate passed. `AuditTrace` omits generator profile, ranked evidence, retrieval backend on the two-stage path, the patient synopsis used as the query, the hook instance, and the card uuid. The error path sets a degraded flag and does not store the final answer, the exception class, or a policy decision. `LOG_REDACT_PHI` defaults true and has no reader, so the stored query and passage text are not covered by that flag. Add one final policy-decision entry for the decision that produced the card. Persist the generator profile, the model id, the retrieval backend, the hook instance, the card uuid, the patient id, and a redacted digest of the retrieval query. On failure, store the final answer and the exception class. Make the redaction flag apply to that write. For a CDS or full-pipeline response, persist that checkpoint before the HTTP body, with one retry. If the write fails twice, return the system-failure card and no clinical summary that claims acceptance. ## A 7B loop needs a trace test, not another orchestrator

The local generator is a 7B LLaMA with **`max_position_embeddings` 2048** ([DaRE-TIES config](https://huggingface.co/MedSwin/MedSwin-DaRE-TIES-KD-0.7/resolve/main/config.json)). The server rejects a prompt whose tokens plus `max_new_tokens` exceed the loaded window with **HTTP 422**. It does not truncate. Specialist compaction caps the passage block at **1400** characters. `call_claim_agent` always passes the claim schema, and the client prepends a second system message with the full schema instruction. Completion length is clamped. Prompt length is never budgeted against the window. The tests assert character caps on the passage block. They do not count the full message, including the schema. Cloud specialists embed the same schema twice, once in the shared system message and once in the prepended instruction. Budget the rendered prompt, schema line plus specialist system plus user suffix, and shrink the passage block until the sum fits the window the server enforces, with a margin. Merge the schema into the existing system line instead of prepending a second copy. The DaRE tokenizer config sets **`model_max_length` 512**, and the server takes the minimum of the config limit and the tokenizer limit, so the 512 cap can bind unless an operator overrides it ([tokenizer config](https://huggingface.co/MedSwin/MedSwin-DaRE-TIES-KD-0.7/raw/main/tokenizer_config.json)). The budget has to use that loaded window. A hoped-for 2048 that the process does not enforce will 422 the specialist and return an empty claim batch ([specialist agent ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/specialist_agent_gaps.md)).

What fits in that window is a fixed, code-routed graph: one retrieve, a non-LLM gate, sequential specialists that return claims with passage ids, and a hard cap of a few loops. Abstain is a branch. The full pipeline already runs quality, chart, guideline, safety, and critic in sequence inside one process. That sequence is the right local pattern. llama.cpp divides context by parallel slots, so six slots on a 2048 window leave on the order of a few hundred tokens each. Sequential calls on one slot are the pattern that preserves the window ([llama.cpp discussion 13606](https://github.com/ggml-org/llama.cpp/discussions/13606)). No fetched source runs LangGraph, the OpenAI Agents SDK, Anthropic’s research system, or Magentic at about 7B parameters and a 2048-token window. Anthropic measured their pattern on Claude Opus 4 and Sonnet 4, wrote the plan out because truncation starts above **200,000** tokens, and found multi-agent runs used about **15×** the tokens of chat ([Anthropic multi-agent research system](https://www.anthropic.com/research/multi-agent-research-system)). LongFuncEval, which is not a 7B-at-2048 study, reports drops of **7% to 85%** as the tool catalogue grows, **7% to 91%** as tool responses lengthen, and **13% to 40%** as multi-turn history lengthens, across the long-context models in that paper ([LongFuncEval](https://arxiv.org/abs/2505.10570)). A tool-stability paper found empty-parameter errors improved with scale for Qwen2.5-Instruct, from a drop of **−5.1** at 7B to **−0.2** at 72B, and found that wrong parameter values did not show the same gain. Cell-level 7B scores from that paper’s tables were misaligned in the extract and are not quoted ([Tool-agent stability](https://arxiv.org/pdf/2506.21967v1.pdf)). Magentic’s per-round ledger is an extra full-context JSON object with five nested fields. That is the call a 2048-token specialist should not make. CURA’s entropy stop is useful if the entropy comes from retrieval scores. Their reported council used GPT-4.1. It is not a 7B result ([CURA PDF](https://papers.miccai.org/miccai-2026/paper/2024_paper.pdf)).

The specialist contract has to match the gate. Every specialist currently sees all shared passages in the prefix, while the suffix lists only the filtered chunk ids. The chart prompt says to use only chart passages. The prefix still shows guideline, literature, and safety text. The test checks suffix ids. It does not check that disallowed headers are absent. When no passage matches the specialist’s source filter, `or passages` resets the allow-list to every candidate. On an empty filter, pass no passages and return a note that this specialist had nothing to read. Do not widen the citation set. Schema-only model output parses as an empty object, `parse_claims` returns zero claims, and `degraded` stays false, so the loop treats the specialist as successful. Empty content does the same. Mark schema-echo and empty payloads as degraded. Local synthesis omits passage bodies past 6 blocks or 2800 characters, while the valid-id line still lists every id in the bundle. The renderer accepts any id in that allow-set, including a bare token in the prose. The test expects `cpg-1` to be cited from the sentence “Use [safety-1] before cpg-1” when `evidence_used` is empty. Intersect citations with the ids whose text was actually shown. On local JSON failure, the raw string becomes the answer with no degraded flag. The cloud path re-raises. Set the degraded flag, and fail the citation join. Valid JSON with the wrong chunk id is the small-model failure that schema checks do not catch. The Constraint Tax, on sub-3B suites rather than on this 7B, raised schema validity from **61.5%** to **100%** while answer accuracy fell from **19.7%** to **11.0%** ([The Constraint Tax](https://arxiv.org/html/2605.26128)). The transfer is the join, not the percentage. Drop any cited id that is absent from the accepted bundle, abstain, and keep the ids in the trace. Do not let claim confidence satisfy a missing facet. The facet still needs the ledger’s lower bound. When `AGENT_PASSAGE_LIMIT` is set, passage selection follows list order and can drop safety chunks. Always prioritise safety passages before the limit. Local specialist completions are hard-capped at **96** tokens, which can cut a multi-claim critic JSON in half. Scale that cap with the room left in the window. Compaction currently follows the process-wide backend setting, while the token cap follows the client. Use one resolver ([specialist agent ledger](../research_notes/MedSwin%20agentic%20runtime%20quality/specialist_agent_gaps.md)).

Prefix stability is the local optimisation that survives those cuts. Put the immutable safety text, the tool schema, and the shared claim prefix first. Put the patient and the retrieved spans last. Do not rewrite the shared prefix mid-request. A change at byte N invalidates every cache breakpoint at or after N on hosts that cache rendered bytes ([Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)). OpenAI’s automatic cache starts at a **1024-token** prefix, which a 2048-token local call will often never reach ([OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)). The local server has no provider cache field. It can still reuse KV inside one process when the prefix bytes are stable, and it currently re-tokenises the full prompt on every HTTP call. Safety instructions stay in the reserved prefix. Compact duplicate chunks and older tool results. Do not summarise the contraindication line into a paraphrase and then drop the source span. Lost-in-the-middle effects are strongest when the input occupies about half the window or less, so on a 2048-token backbone the decisive warning belongs in the suffix, beside the citation stub ([Positional biases](https://arxiv.org/abs/2508.07479)). Catfish reports silent-agreement rates above **61%** for MedAgents and MDAgents on a hard slice built from MedQA and PubMedQA, and **17.0%** for their critic method on MedQA. ## Conclusion

The gate is already the right authority, and the surrounding layers are what make its vote untrustworthy. A fusion fallback, a keyword-free source match, a packed short passage, a dropped caution, and a cross-facet warning each produce an accept or an abstain that the predicates do not mean. Closing those paths, without moving 0.55 and without reopening the shipped pairing rule, is the reinforcement. The card, the session, and the trace then have to carry that same decision, bound to one user and one patient, or the clinician sees silence, a warning that is actually a crash, or another patient’s chart.

A new orchestrator would add a stall bit and a default of thousands of steps on top of a loop that already has a cap of three and already compares chunk ids. The work that changes the next accept is smaller and stricter: calibrated inclusion, same-drug conflicts on the full text, patient-scoped retrieval, a card that cannot be empty or untraceable, and a test that fails when the trace and the card disagree. Until those locks exist, a faster local server or a larger cloud model accelerates a decision the control plane has not earned.
